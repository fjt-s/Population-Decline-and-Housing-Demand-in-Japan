# データ取得計画

## 現在の状況（2026-08-17時点）

| データ | 状況 | 備考 |
|---|---|---|
| 国勢調査（人口・世帯数） | ✅ 取得済み | 2000〜2020年・市区町村別、`data/raw/census_*.json` |
| 住宅着工件数 | ✅ 取得済み | 2011〜2023年・市区町村別、`data/raw/housing_starts_*.json` |
| 公示地価 | ✅ 取得済み | 2022〜2026年・市区町村コード付き、`data/raw/land_price_*.json` |

`XPT002`（タイル方式）で2012〜2021年まで遡ることも検討したが、全国カバーには z=13 で約34万タイル/年
必要と判明し非現実的と判断（[未決定事項](#未決定事項)参照）。`XCT001`で取得可能な2022〜2026年の5年分を採用。

## 構成

```
scripts/
  estat_client.py        e-Stat API 3.0 の薄いラッパー（getStatsList / getStatsData）
  reinfolib_client.py     不動産情報ライブラリ API の薄いラッパー（XYZタイル対応）
  fetch_census.py         国勢調査（人口・世帯数）取得スクリプト
  fetch_housing_starts.py 住宅着工件数 取得スクリプト
  fetch_land_price.py     公示地価・地価調査 取得スクリプト
data/
  raw/                    API から取得した生データ（gitignore対象）
  processed/              集計・整形後のデータ（gitignore対象）
  external/               手動ダウンロードした補助データなど（gitignore対象）
.env.example              ESTAT_APP_ID / REINFOLIB_API_KEY のテンプレート
```

APIキー発行後は `.env.example` を `.env` にコピーし、値を入れて `pip install -r requirements.txt`。

## 各データソースの詳細

### 1. 国勢調査（人口・世帯数）— ✅ 取得済み

- API: e-Stat API（`getStatsList` / `getStatsData`）
- 政府統計コード: `00200521`
- 対象年: 2000, 2005, 2010, 2015, 2020（2025年国勢調査は結果公表後に追加）
- 地域粒度: 市区町村コード（5桁, `@area`）単位で人口・世帯数・5年間の増減率・面積・人口密度が取得可能
- 統計表ID（年ごと、`fetch_census.py` の `CENSUS_TABLES` に固定済み）:
  | 年 | statsDataId |
  |---|---|
  | 2000 | 0003391075 |
  | 2005 | 0003408216 |
  | 2010 | 0003411171 |
  | 2015 | 0003148500 |
  | 2020 | 0003433220 |
- `python scripts/fetch_census.py fetch-all` で5年分を `data/raw/census_<year>_<id>.json` に保存済み（各10〜14MB）
- 面積（`area_km2`、人口密度の算出用）も各年の表から取得し `build_dataset.py` の `population_households.csv` /
  `merged_panel.csv` に含めている（2000/2005/2010は cat01=140、2015は tab=103、2020は tab=2020_47）。
- **⚠️ 2020年の統計表 `0003433220` には現数値の総人口が含まれていない**（2015年人口を2020年境域に
  組み替えた比較用の値のみ）。現数値人口は別表 `0003433219`（男女別人口）の `tab=2020_01`,
  `cat01=0`（総数）から取得し、`data/raw/census_2020_pop_0003433219.json` に保存済み。前処理では
  この2ファイルを突合して2020年の人口・世帯数を組み立てる。

### 2. 住宅着工件数 — ✅ 取得済み（ただし要注意点あり）

- API: e-Stat API（同上）
- 政府統計コード: `00600120`（建築着工統計調査）
- **「建築物着工統計 表7-2」を使用**（市区町村別、用途別（大分類）／建築物の数・床面積・工事費予定額）
  - 「住宅着工統計」本体の確報（新設住宅着工戸数）は都道府県別までしか出ないため使えない。
  - `cat01`（用途）のうち住宅系は `12`（居住専用住宅）`13`（居住専用準住宅）`14`（居住産業併用建築物）。
    これらを合算したものを「住宅着工件数」の近似値として使う（新設住宅着工戸数とは定義が異なる点に注意）。
  - 統計表ID:
    | キー | statsDataId | 対象年 |
    |---|---|---|
    | calendar_2011_2019 | 0003114492 | 2011〜2019年（暦年） |
    | fiscal_2020_2023 | 0004019381 | 2020〜2023年度 |
    | (参考) fiscal_2011_2019 | 0003117502 | 2011〜2019年度 |
  - `python scripts/fetch_housing_starts.py fetch-all` で `data/raw/housing_starts_*.json` に保存済み
- **⚠️ 3つの重要な制約**:
  1. **市区町村別データは2011年分以降のみ**。国勢調査は2000年から取れるが、住宅着工の市区町村別は
     2011年が下限（2000〜2010年は e-Stat 上に存在しない）。
  2. **2020年に集計基準が「暦年」→「年度」に切り替わっている**（建築基準法別表改正に伴う区分変更）。
     2011-2019と2020以降を単純に結合する際はこの切り替わりに注意する。
  3. **e-Stat API は1リクエストあたり最大10万件までしか返さない**（`RESULT_INF.NEXT_KEY` でページング
     が必要）。当初 `estat_client.get_stats_data` はページングに未対応で、暦年版は97.7万件中10万件
     （約10%）しか取得できていなかった。`estat_client.get_stats_data_all`（`startPosition` を進めながら
     全ページ結合）を追加し、`fetch_housing_starts.py` を修正して再取得済み（全件: 暦年97.7万件、
     年度基準2011-2019が97.6万件、2020-2023年度が34.0万件）。国勢調査データは各年10万件未満のため
     影響なし。

### 3. 公示地価・地価調査 — ✅ 取得済み

- API: 不動産情報ライブラリ API。全国取得には **`XCT001`（鑑定評価書情報API）を採用**（決定）。
  - 都道府県コード（`area`, 01〜47）指定の非タイル方式なので、47都道府県をループするだけで全国を
    網羅でき、`XPT002`（XYZタイル方式）で全国を走査する場合（数十万タイル規模）に比べて現実的。
  - `division`（用途区分）は住宅需要分析の主眼に合わせて `00`（住宅地）をデフォルトにする。
  - レスポンスに都道府県コード・市区町村コード・緯度経度・㎡単価などが含まれ、市区町村単位への
    集計はこの後の前処理で行う。
  - **⚠️ 年の制約**: `year` は 2022〜2026年のみ指定可能（2026年8月時点のAPI仕様）。国勢調査
    （2000〜2020年、5年おき）と同じ年での突合ができない。直近の地価水準として横断的に使う運用とする。
  - `python scripts/fetch_land_price.py <year>` で `data/raw/land_price_<year>_div00.json` に保存済み
    （2022〜2026年の5年分、各年35,000〜37,000件）。
  - **`XPT002`（1995〜2024年、タイル方式）による長期補完は見送り**: z=13でも全国カバーには
    約34万タイル/年 必要と判明（実測）。1年分だけでも数万回のAPI呼び出しが必要で非現実的と判断。
    対象地域を数都市に絞れば別（`reinfolib_client.get_land_price_tile` / `tiles_for_bbox` を参照）。

## 決定事項

- **地域粒度**: 市区町村単位 → 住宅着工は「建築物着工統計 表7-2」を使用
- **対象地域**: 全国（仮説検証・外れ値探索のため地域を絞らない）→ 地価は `XCT001` を都道府県ループで取得

## 未決定事項

1. **対象年range**: 国勢調査（5年おき、2000-2020）・住宅着工（年次）・地価（`XCT001`は2022-2026年限定）の
   年次がズレるため、分析設計上どう揃えるか（例: 直近の地価水準を横断的な説明変数として使う等）
   → 暫定対応として `build_dataset.py` では year × area_code の外部結合（欠損はNaN）としている。

## 4. 統合（市区町村コード単位のパネルデータ）— ✅ 完了

- `python scripts/build_dataset.py` で3データソースを `area_code`（5桁市区町村コード）と `year` で
  結合し、`data/processed/` に出力:
  - `population_households.csv`（国勢調査、2000/2005/2010/2015/2020）
  - `housing_starts.csv`（住宅系着工の棟数・床面積・工事費予定額、2011〜2023、`period_type` で
    暦年/年度を区別）
  - `land_price.csv`（住宅地の公示地価、市区町村内の平均・中央値・地点数、2022〜2026）
  - `merged_panel.csv`（上記3つを外部結合したロング形式パネル。36,330行、市区町村コード3,723種）
- **市区町村コードの抽出ロジック**: 各e-Statテーブルは「全国／都道府県／市区町村」の階層を
  年ごとに異なる `@level` 番号で表現するため、level番号ではなく「他のどのコードの parentCode にも
  なっていない」leafノードを市区町村単位とみなして抽出している（`_leaf_area_codes`）。
  - **⚠️ 罠**: 2010年・2015年の国勢調査表には、`@level` だけでは判別できない「フラットな集計行」
    が同じ都道府県の下に市区町村と混在していた: 「(旧 ○○市)」（合併前の旧市区町村、比較用）、
    「○○郡」「○○県市部/郡部」「全国市部/郡部」（郡・都市/郡部単位の集計）、北海道の
    「○○振興局/支庁」（広域行政区分）。これらを除外せず単純にleaf判定しただけの初期実装では
    2010年が4,003件、2015年が4,436件と実際の市区町村数（各年とも概ね1,870〜1,900件）の2倍以上に
    膨れ上がった。名称パターンでの除外を追加し、2010年1,901件・2015年1,897件に修正済み
    （周辺年と整合）。
  - 検証: 夕張市（人口減少・財政再生団体として著名）で人口14,791→7,341人（2000→2020年）、
    住宅着工が年数件、地価が2,875→2,450円/m²（2022→2026年）と、既知の実態と整合する推移を
    確認済み。
